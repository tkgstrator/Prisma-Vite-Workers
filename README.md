# Prisma-Vite-Workers

Cloudflare Workers fullstack template with local-first development.

- **Backend**: [Hono](https://hono.dev/) (`@hono/zod-openapi`) with auto-generated OpenAPI docs ([Scalar](https://scalar.com/) at `/docs`)
- **Frontend**: React 19 + [TanStack Router](https://tanstack.com/router) (file-based) + [TanStack Query](https://tanstack.com/query) + Tailwind CSS v4
- **Database**: Cloudflare D1 via [Prisma](https://www.prisma.io/) (`@prisma/adapter-d1`)
- **Storage**: Workers KV / R2 with working sample routes
- **Realtime**: SQLite-backed Durable Object with RPC + WebSocket Hibernation
- **Tooling**: Bun / Vite 8 (`@cloudflare/vite-plugin`) / Biome (+ GritQL plugins) / TypeScript

Everything (KV, R2, D1, Durable Objects, WebSockets) runs locally through a single `vite` dev server — no Cloudflare account required until you deploy.

## Getting started

```sh
bun install
bun run dev
```

`bun run dev` automatically runs `prisma generate`, `wrangler types` and applies pending D1 migrations to the local database, then starts Vite at http://localhost:5173.

The sample app has four demo pages:

| Page | Binding | What it shows |
|---|---|---|
| `/todo` | D1 (`DB`) | Todo CRUD through Prisma + `@prisma/adapter-d1` |
| `/kv` | KV (`KV`) | list / get / put / delete |
| `/r2` | R2 (`BUCKET`) | File upload / download with ETag caching |
| `/counter` | DO (`COUNTER`) | RPC + realtime WebSocket broadcast (open two tabs!) |

API reference is served at `/docs` (OpenAPI 3.1 via Scalar).

## Architecture

```
src/
├── server/                  # Cloudflare Worker (Hono)
│   ├── index.ts             # OpenAPIHono entry, re-exports Durable Objects
│   ├── routes/              # One OpenAPIHono sub-app per feature
│   └── durable-objects/     # DO classes (SQLite storage + WebSocket Hibernation)
├── app/                     # React SPA
│   ├── main.tsx
│   └── routes/              # TanStack Router file-based routes
└── generated/prisma/        # prisma generate output (gitignored)
```

`@cloudflare/vite-plugin` reads `wrangler.toml`, so bindings are declared once and work identically in dev (miniflare emulation) and production. Static assets are served with SPA fallback; `/api/*`, `/docs` and `/openapi.json` are handled by the Worker first (`run_worker_first`).

## Database workflow (Prisma + D1)

D1 does not support `prisma migrate dev`. Instead, migrations are plain SQL files in `prisma/migrations/`, generated by `prisma migrate diff` and applied by `wrangler d1 migrations apply`:

```sh
# 1. Edit prisma/schema.prisma

# 2. Generate a migration SQL from the diff against the local D1 state
bun run migrate:new > prisma/migrations/0002_add_something.sql

# 3. Apply locally (also runs automatically before `bun run dev`)
bun run migrate:apply

# 4. Regenerate the Prisma client
bun run generate

# 5. Apply to the remote database when deploying
CLOUDFLARE_ENV=staging bun run migrate:remote
```

> [!WARNING]
> Do not use `wrangler d1 execute --local --file` to apply raw SQL: depending on how it is invoked it may write to a different SQLite file than the one the dev server (miniflare) reads. Always go through `wrangler d1 migrations apply DB --local`, which shares `.wrangler/state` with the Vite dev server.

## Deployment

1. Create the real resources:

   ```sh
   bunx wrangler kv namespace create KV
   bunx wrangler r2 bucket create prisma-vite-workers
   bunx wrangler d1 create prisma-vite-workers
   ```

2. Replace the `<REPLACE_ME>` IDs in `wrangler.toml` (`[env.staging]` / `[env.production]` sections).

3. Deploy:

   ```sh
   CLOUDFLARE_ENV=staging bun run deploy     # default
   CLOUDFLARE_ENV=production bun run deploy
   ```

The GitHub Actions workflow (`deployment.yaml`) deploys automatically when a PR is merged: into the default branch → `production`, into any other configured branch → `staging`. Set `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets.

## Scripts

| Script | Description |
|---|---|
| `bun run dev` | Start the dev server (generates client/types + applies migrations first) |
| `bun run build` | Type check + production build |
| `bun run deploy` | Build + `wrangler deploy` (env from `CLOUDFLARE_ENV`, default `staging`) |
| `bun run generate` | `prisma generate` + `wrangler types` |
| `bun run migrate:new` | Print migration SQL diff (redirect to a new file) |
| `bun run migrate:apply` | Apply migrations to local D1 |
| `bun run migrate:remote` | Apply migrations to remote D1 |
| `bun run typecheck` | `tsc -b --noEmit` |
| `bun run lint` | Biome check with auto-fix |
| `bun test` | Run tests |

## Code style

Biome enforces the base rules plus custom [GritQL plugins](./biome-plugins/): no `let`, no `while`, no `as` assertions (except `as const`), no `??`/`||` fallbacks, no bare `z.string()`, no `new Date()` (use dayjs), and more. Run `bun run lint` before committing. Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (checked by commitlint in CI).
